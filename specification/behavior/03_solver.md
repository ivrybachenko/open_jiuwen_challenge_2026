# Агент

- Состояние: реализовано
- Читатель: разработчик и coding-агент; организатор читает `README.md`
- Проверки: [таблица проверок](#как-проверить)

## Модель

- На прогон выбирается одна или две модели из четырёх разрешённых
  регламентом.
- По умолчанию — `qwen3.6-35b-a3b-noreason`; `--model` и `LLM_MODEL`
  перекрывают выбор для первой волны.
- `--wave2-model` и `LLM_WAVE2_MODEL` задают отдельную модель второй волны.
  Без флага вторая волна использует ту же модель, что и первая.
- Запросы идут на OpenAI-совместимый прокси `LLM_BASE_URL` с ключом
  `LLM_API_KEY` через `openjiuwen.core.foundation.llm.init_model`.
- Таймаут одного вызова — `--model-timeout` (180 секунд), `temperature=0`.
- `max_tokens` задаётся отдельно для волн: 1000 в первой и 4000 во второй.
- В журнале попыток поле `model` содержит фактическую модель хода.

## Формат ответа

- У агента нет списка инструментов. Его ответ целиком считается
  bash-скриптом.
- Системный промпт на английском требует **ровно один** fenced-блок с полным
  самодостаточным скриптом, который инспектирует файлы, считает и пишет
  `answer.txt` за одно исполнение. Текст до и после блока запрещён.
- Харнесс исполняет содержимое блока. Если модель всё же вернула несколько
  Markdown-блоков, исполняется последний: это защитное поведение для
  провайдеров, которые кладут рассуждения в `content`. Если блоков нет,
  ответ исполняется as-is.
- Скрипт запускается командой `cd <workspace> && bash <script>` с таймаутом
  `--turn-timeout` (120 секунд). Копия скрипта лежит в рабочем каталоге под
  именем `.harness_step_NN.sh`, поэтому `dirname "$0"` указывает на файлы
  задачи; после исполнения копия удаляется.
- stdout и stderr объединяются, обрезаются до
  `--script-output-max-chars` (4000 символов) и возвращаются агенту вместе с
  кодом возврата или отметкой таймаута.

## Системный промпт

Промпт требует:

- ровно один fenced-блок с полным скриптом на ход, без текста до и после;
- один полный скрипт, а не одну исследовательскую команду;
- писать в `answer.txt` только финальный ответ: число или короткую строку
  для math/data/search и `DONE` для coding;
- при противоречивых условиях или отсутствии значения писать `IMPOSSIBLE`
  первой строкой, а не выдумывать приблизительный ответ;
- проверять, что извлечённые значения непустые и правдоподобные.

Промпт не содержит слов `budget`, `tokens left`, `spending limit` и не
сообщает агенту остаток бюджета.

## Обзор рабочей директории

Обзор строится до первого вызова модели и ограничен
`--overview-max-tokens` (1500, оценка по символам).

- `pwd`, `which python`, список файлов и каталогов;
- большие группы файлов сворачиваются в шаблоны `data/*.csv (N files)`;
- большие файлы показываются размером и не читаются;
- для CSV/TSV/PSV показываются заголовок и пример первой строки; одинаковые
  заголовки печатаются один раз;
- найденные `test*.py` запускаются, их вывод или `PASS` попадает в обзор;
- текст задачи добавляется всегда; при нехватке лимита сначала сокращаются
  список, датасеты и тесты.

Обзор строится один раз на задачу и сохраняется в состоянии.

## Жизненный цикл

- `Runner.start()` вызывается один раз на прогон; `Runner.stop()` — в
  `finally`.
- На каждую задачу создаётся состояние в
  `<agent-workspace>/<task_id>/state.json`: обзор, история сообщений, ходы,
  расход, лучший ответ.
- Состояние переживает повторный запуск процесса на том же каталоге задач и
  с теми же моделями волн; при другом каталоге или модели задача начинается
  заново.
- После каждого хода состояние и `solutions.json` перезаписываются атомарно.

## Известные ограничения

- Нет инструментов и песочницы уровня отдельного инструмента: скрипт агента
  может делать всё, что разрешено контейнеру.
- Модель иногда кладёт рассуждения в `content`; последний Markdown-блок
  спасает не все такие ответы.
- Нет проверки правильности ответа: `solved` означает «ответ сдан», а не
  «ответ верный».
- Нет третьей волны и нет выбора модели по задаче; есть только отдельная
  модель второй волны.
- Модель без ризонинга дешевле, но в эксперименте `0003` иногда уступала
  reasoning-модели на сложных `search`-задачах; `--model` позволяет вернуть
  R без изменения кода.

## Как проверить

Общие команды и флаги — в [`evaluation/README.md`](../../evaluation/README.md).
Все команды запускаются из корня репозитория, кроме harness-тестов, где нужен
`cd harness`.

| ID | Уровень | Что подтверждает | Проверка | Ожидаемо |
| --- | --- | --- | --- | --- |
| V-1 | быстрая | промпт без инструментов и бюджета, модель по умолчанию, выбор модели второй волны, скрипт исполняется | `cd harness && uv run python -m unittest test.test_bash_agent test.test_config test.test_shell test.test_predictor` | все тесты OK |
| V-2 | быстрая | обзор ограничен и обрабатывает ловушки | `cd harness && uv run python -m unittest test.test_overview` | все тесты OK |
| V-3 | интеграционная | агент решает задачу через bash и `answer.txt` | `python -m evaluation.harness_task_checker --task math/solvable/0001 --keep` | `solved=yes`, в отчёте есть токены и время |
| V-4 | интеграционная | coding-задача решается правкой файла | `python -m evaluation.harness_task_checker --task coding/solvable/0001 --keep` | `solved=yes`, тесты проходят |

`--keep` сохраняет временный каталог прогона, чтобы разобрать артефакты агента.
