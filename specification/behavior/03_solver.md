# Агент

- Состояние: реализовано
- Читатель: разработчик и coding-агент; организатор читает `README.md`
- Проверки: [таблица проверок](#как-проверить)

## Модель

- На прогон выбирается одна модель из четырёх разрешённых регламентом.
- По умолчанию — `qwen3.6-35b-a3b`.
- Переключение модели между вызовами не реализовано: модель фиксируется на
  весь запуск.
- Запросы идут на OpenAI-совместимый прокси `LLM_BASE_URL` с ключом
  `LLM_API_KEY`; таймаут одного вызова — 180 секунд, `max_tokens` — 8192.

## Устройство агента

На каждую задачу создаётся отдельный `DeepAgent` из openJiuwen:

- системная инструкция требует работать только в текущем каталоге, не
  редактировать тесты, вызвать `write_answer` ровно один раз и для
  coding-задач вернуть `DONE`;
- `SysOperationRail` даёт инструменты `bash`, `read_file`, `write_file`,
  `edit_file`, `glob`, `grep`, `list_dir`;
- дополнительный инструмент `write_answer` записывает `answer.txt`;
- `TokenTrackingRail` собирает расход токенов;
- `FinishAfterAnswerRail` принудительно завершает ReAct-цикл сразу после
  `write_answer`, чтобы не тратить лишний вызов модели.

Ограничения агента:

- `max_iterations` по умолчанию 12;
- `max_tokens` 8192 на один вызов модели;
- `restrict_to_work_dir=True`;
- task loop и task planning отключены;
- мультимодальное чтение изображений отключено;
- security rail отключён.

## Рабочий каталог и песочница

- `cwd` агента — `workspace/` задачи, если он есть, иначе корень задачи.
- Артефакты агента складываются в `/tmp/agent-workspaces/<task_id>`.
- Общий `SysOperation` создаётся один раз на прогон; песочница ограничивает
  абсолютные пути вне каталога задачи и workspace агента.
- Ограничение best-effort: относительный выход через `..` не отлавливается.

## Жизненный цикл

- `Runner.start()` вызывается один раз на весь прогон.
- На каждую задачу создаётся уникальный агент и `conversation_id`.
- После задачи сессия освобождается, способности агента удаляются.
- `Runner.stop()` вызывается в `finally`, чтобы не потерять уже записанные
  результаты.

## Известные ограничения

- Нет динамического выбора модели и планировщика, который менял бы стратегию
  по ходу решения.
- Нет сохранения полной траектории сообщений и вызовов инструментов.

## Как проверить

Общие команды и флаги — в [`evaluation/README.md`](../../evaluation/README.md).
Все команды запускаются из корня репозитория.

| ID | Уровень | Что подтверждает | Проверка | Ожидаемо |
| --- | --- | --- | --- | --- |
| V-1 | интеграционная | агент решает задачу и возвращает ответ | `python -m evaluation.harness_task_checker --task math/easy/0001 --keep` | `solved=yes`, в отчёте есть токены и время |
| V-2 | интеграционная | рабочие артефакты сохраняются для разбора | та же команда с `--keep` | временный каталог и `harness.stdout_tail` доступны в отчёте |

`--keep` сохраняет временный каталог прогона, чтобы разобрать артефакты агента.
