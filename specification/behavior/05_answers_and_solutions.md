# Ответы и файл решений

- Состояние: реализовано
- Читатель: разработчик и coding-агент; организатор читает `README.md`
- Проверки: [таблица проверок](#как-проверить)

## `answer.txt`

- Ответ пишет сам агент: его bash-скрипт должен создать `answer.txt` в
  рабочем каталоге.
- Харнесс не считает ответом вывод скрипта, `DONE` в тексте или содержимое
  другого файла — только непустой `answer.txt`.
- Если `workspace/` существует, найденный ответ дополнительно пишется в
  корень задачи: регламент требует файл в каталоге задачи, а инструкции — в
  текущем каталоге.
- Перед решением задачи старые `answer.txt` удаляются, чтобы прошлый ответ не
  был засчитан.
- После каждого хода харнесс читает `answer.txt` из рабочего каталога или
  корня задачи. Если файл появился, дополнительных вызовов модели в этом ходе
  нет.
- Если первая строка ответа — `IMPOSSIBLE`, ответ сохраняется, но
  `solved=false`: баллы за такую задачу не начисляются. Вторая волна может
  перепроверить задачу, если эвристика сочла её перспективной.

## `solutions.json`

Файл перезаписывается атомарно после каждого хода: сначала пишется временный
файл, затем выполняется `os.replace`. Пропуск записи означает потерю задачи,
поэтому запись идёт после каждого хода и после восстановления состояния.

Путь выбирается по порядку: `--out`, затем `OUT`, затем
`<tasks-dir>/solutions.json`. Если запись по выбранному пути невозможна
(например, `OUT` задан, но не смонтирован в read-only контейнер), харнесс
пробует `<tasks-dir>/solutions.json`, затем `/tmp/solutions.json`, пишет
предупреждение и продолжает прогон. Ошибка записи не завершает процесс:
иначе терялись бы и последующие ответы.

Структура:

```json
{
  "updated_at": "2026-01-01T00:00:00+00:00",
  "total_score": 10.0,
  "total_cost": 1234,
  "solutions": {
    "math_0000": {
      "task_id": "math_0000",
      "reward": 5.0,
      "solved": true,
      "answer": "389",
      "input_tokens": 1000,
      "output_tokens": 100,
      "cost": 200,
      "note": "answer_kind=value; attempts=1",
      "updated_at": "2026-01-01T00:00:00+00:00"
    }
  }
}
```

Важно:

- `solved` означает «получен пригодный ответ», а не «ответ правильный».
  `IMPOSSIBLE` даёт `solved=false`. Корректность проверяют скрытые тесты или
  `evaluation/`.
- `total_score` — сумма `reward` по записям с `solved=true`; она может быть
  выше фактического результата, пока ответы не проверены.
- `total_cost` — сумма `cost` по всем записям.
- `cost`, `input_tokens` и `output_tokens` накапливаются по всем ходам задачи,
  включая вторую волну.
- В `note` фиксируются вид ответа, число ходов, признак второй волны,
  `IMPOSSIBLE`, обещание эвристики и последняя ошибка.

## Восстановление

- Состояние задачи лежит в `<agent-workspace>/<task_id>/state.json`.
- При повторном запуске процесса на том же каталоге задач и с той же моделью
  харнесс продолжает с сохранённого места: уже сделанные ходы не повторяются,
  а `solutions.json` восстанавливается из состояния.
- Если каталог задачи или модель изменились, состояние игнорируется и задача
  начинается заново.
- Флаг `--no-resume` отключает восстановление.

## Повторный запуск

- При старте существующий `solutions.json` читается и загружается в память.
  Если основной файл недоступен, читается запасной (`<tasks-dir>`, затем
  `/tmp`), поэтому прогон продолжается и после смены пути.
- Расход и число токенов восстанавливаются из `solutions.json`.
- Задачи без сохранённого состояния решаются заново.

## Как проверить

Общие команды и флаги — в [`evaluation/README.md`](../../evaluation/README.md).
Все команды запускаются из корня репозитория.

| ID | Уровень | Что подтверждает | Проверка | Ожидаемо |
| --- | --- | --- | --- | --- |
| V-1 | интеграционная | `answer.txt` появляется в рабочем каталоге и корне задачи | `python -m evaluation.harness_task_checker --task coding/solvable/0001 --keep` | оба файла существуют и непусты |
| V-2 | быстрая | `IMPOSSIBLE` не считается решённой задачей | `cd harness && uv run python -m unittest test.test_features test.test_bash_agent` | `solved=false`, вид ответа `impossible` |
| V-3 | быстрая | состояние переживает повторный запуск | `cd harness && uv run python -m unittest test.test_bash_agent` | состояние загружается и не теряет ходы |
| V-4 | ручная | структура `solutions.json` | открыть файл после прогона | есть `updated_at`, `total_score`, `total_cost`, `solutions`; у задачи есть `cost`, `note`, накопленные токены |

`answer_evaluator` не запускает агент и не требует `LLM_API_KEY`.
