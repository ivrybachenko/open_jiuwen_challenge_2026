# Ответы и файл решений

- Состояние: реализовано
- Читатель: разработчик и coding-агент; организатор читает `README.md`
- Проверки: [таблица проверок](#как-проверить)

## `answer.txt`

- Агент вызывает инструмент `write_answer`, который сразу пишет
  `answer.txt` в рабочий каталог задачи.
- Если `workspace/` существует, тот же ответ пишется и в корень задачи:
  регламент требует файл в каталоге задачи, а инструкции — в текущем
  каталоге.
- Пустой ответ инструмент отклоняет.
- Перед решением задачи старые `answer.txt` удаляются, чтобы прошлый ответ не
  был засчитан.
- Если инструмент не вызывался, харнесс пытается прочитать `answer.txt` из
  рабочего каталога или корня задачи.

## `solutions.json`

Файл перезаписывается атомарно после каждой задачи: сначала пишется временный
файл, затем выполняется `os.replace`. Пропуск записи означает потерю задачи,
поэтому запись идёт после каждого решения.

Структура:

```json
{
  "updated_at": "2026-01-01T00:00:00+00:00",
  "total_score": 10.0,
  "total_cost": 1234,
  "solutions": {
    "math_0000": {
      "task_id": "math_0000",
      "reward": 5.0,
      "solved": true,
      "answer": "389",
      "input_tokens": 1000,
      "output_tokens": 100,
      "cost": 200,
      "note": "result_type=answer; answer via write_answer",
      "updated_at": "2026-01-01T00:00:00+00:00"
    }
  }
}
```

Важно:

- `solved` означает «ответ сдан», а не «ответ правильный». Корректность
  проверяют скрытые тесты или `evaluation/`.
- `total_score` — сумма `reward` по записям с `solved=true`; она может быть
  выше фактического результата, пока ответы не проверены.
- `total_cost` — сумма `cost` по всем записям.
- `cost` считается по формуле соревнования.

## Повторный запуск

- При старте существующий `solutions.json` читается и загружается в память.
- Уже решённые задачи не пропускаются: харнесс снова проходит по всем задачам
  и перезаписывает их записи.
- `total_score` и `total_cost` при загрузке считаются по старым записям, а
  затем обновляются после каждой новой задачи.

## Как проверить

Общие команды и флаги — в [`evaluation/README.md`](../../evaluation/README.md).
Все команды запускаются из корня репозитория.

| ID | Уровень | Что подтверждает | Проверка | Ожидаемо |
| --- | --- | --- | --- | --- |
| V-1 | интеграционная | `answer.txt` появляется в рабочем каталоге и корне задачи | `python -m evaluation.harness_task_checker --task coding/easy/0001 --keep` | оба файла существуют и непусты |
| V-2 | быстрая | готовый ответ оценивается без запуска агента | `python -m evaluation.answer_evaluator --task math/easy/0001 --answer <answer.txt>` | `solved=yes`, код возврата 0 |
| V-3 | ручная | структура `solutions.json` | открыть файл после прогона | есть `updated_at`, `total_score`, `total_cost`, `solutions`; у задачи есть `cost` и `note` |

`<answer.txt>` — файл с ответом для проверки; `answer_evaluator` не запускает
агент и не требует `LLM_API_KEY`.
