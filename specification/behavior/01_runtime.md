# Сборка и запуск

- Состояние: реализовано
- Читатель: разработчик и coding-агент; организатор читает `README.md`
- Проверки: [таблица проверок](#как-проверить)

## Назначение

Решение собирается в Docker-образ и запускается проверяющей системой с
каталогом задач и ключом LLM-прокси. Версия `0004` использует bash-агента:
ответ модели исполняется как скрипт, а не как вызов инструментов openJiuwen;
незавершённые задачи получают до восьми волн.
По умолчанию выбрана модель без ризонинга; явные `--model` и `LLM_MODEL`
перекрывают её.

## Сборка

`Dockerfile`:

- базовый образ `python:3.12-slim`, закреплён по digest;
- `uv` версии `0.13.7` копируется из официального образа;
- зависимости ставятся из `harness/pyproject.toml` и `harness/uv.lock`
  командой `uv sync --frozen --no-dev`;
- исходники копируются из `harness/src`, entrypoint — `/app/run_agent.py`;
- версия openJiuwen закреплена в `harness/pyproject.toml` (`0.1.19`).

## Запуск

Проверяющая система запускает контейнер с `--read-only`, записываемым
`tmpfs` в `/tmp`, `HOME=/tmp` и каталогом задач в `/data/tasks`:

```bash
docker run ... hack:latest /app/run_agent.py --tasks-dir /data/tasks
```

Контейнер не должен писать в корень файловой системы: всё изменяемое
состояние живёт в `/tmp` и в каталоге задач.

## Параметры

| Параметр | CLI | Переменная | По умолчанию |
| --- | --- | --- | --- |
| Каталог задач | `--tasks-dir` | `TASKS` | `/data/tasks` |
| Файл решений | `--out` | `OUT` | `<tasks-dir>/solutions.json` |
| Бюджет | `--budget` | `BUDGET` | `100000` |
| Модель | `--model` | `LLM_MODEL` | `qwen3.6-35b-a3b-noreason` |
| Модели на волну | — | `HARNESS_WAVE_MODELS` | включены (`1`) |
| Лимит волны 1 | `--wave1-max-tokens` | `HARNESS_WAVE1_MAX_TOKENS` | `1000` |
| Лимит волны 2 | `--wave2-max-tokens` | `HARNESS_WAVE2_MAX_TOKENS` | `4000` |
| Число задач волны 2 | `--wave2-max-tasks` | `HARNESS_WAVE2_MAX_TASKS` | `50` |
| Число волн | `--max-waves` | `HARNESS_MAX_WAVES` | `8` |
| Лимит обзора | `--overview-max-tokens` | `HARNESS_OVERVIEW_MAX_TOKENS` | `1500` |
| Лимит вывода скрипта | `--script-output-max-chars` | `HARNESS_SCRIPT_OUTPUT_MAX_CHARS` | `4000` |
| Таймаут скрипта | `--turn-timeout` | `HARNESS_TURN_TIMEOUT` | `120` |
| Таймаут модели | `--model-timeout` | `HARNESS_MODEL_TIMEOUT` | `180` |
| Каталог агента | `--agent-workspace` | `AGENT_WORKSPACE` | `/tmp/agent-workspaces` |
| Каталог траекторий | `--trajectories-dir` | `TRAJECTORIES_DIR` | не задан (запись выключена) |
| Идентификатор попытки | `--run-id` | `HARNESS_RUN_ID` | не задан |
| Число задач | `--max-tasks` | — | все задачи |
| Восстановление | `--no-resume` | `HARNESS_RESUME=0` | включено |
| Уровень логов | `--log-level` | — | `INFO` |

`--max-iterations` сохранён для совместимости с оценщиками и игнорируется:
число ходов задаётся волнами. `LLM_BASE_URL` и `LLM_API_KEY` передаются
только через окружение. Если `OUT` указывает на каталог, файл решений будет
`<OUT>/solutions.json`. Если файл решений нельзя записать по основному пути,
харнесс пробует `<tasks-dir>/solutions.json`, затем `/tmp/solutions.json` и
продолжает прогон; смена пути пишется в лог как `WARNING`. `--run-id` /
`HARNESS_RUN_ID` — непрозрачный идентификатор попытки: харнесс только
сохраняет его в журнале попыток, сам не генерирует.

## Файловая система

- Корень контейнера только для чтения.
- `/tmp` — единственное место для временных файлов, скриптов и состояния
  агента.
- `/data/tasks` смонтирован с правом записи; туда пишутся `answer.txt` и, по
  умолчанию, `solutions.json`. Если `OUT` задан, но недоступен на запись,
  `solutions.json` тоже уходит в `/data/tasks`, а прогон продолжается.
- Состояние задачи лежит в `/tmp/agent-workspaces/<task_id>/state.json`.
  Оно переживает повторный запуск процесса в том же контейнере, но не
  переживает контейнер.
- Каталог траекторий, если он задан, должен быть доступен на запись. В
  зачётном контейнере флаг не передаётся, поэтому корень остаётся read-only.

## Логи

- Сам харнесс пишет в stdout/stderr на уровне `--log-level`.
- openJiuwen переводится в console-only режим с уровнем `WARNING`, чтобы не
  писать в `./logs` на read-only файловой системе.
- Файловых логов нет. Подробнее — в
  [06_trajectories.md](06_trajectories.md).

## Известные ограничения

- Журнал попыток сохраняется только по флагу `--trajectories-dir`; без него
  харнесс его не пишет.
- Параллельный запуск нескольких сессий не используется: задачи решаются
  последовательно.
- `--max-iterations` больше не влияет на поведение.

Общие команды и флаги — в [`evaluation/README.md`](../../evaluation/README.md).

прогоняет `minimal.yaml` в контейнере.
