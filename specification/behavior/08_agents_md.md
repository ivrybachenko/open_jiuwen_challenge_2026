# Инструкции для coding-агента (AGENTS.md)

- Состояние: реализовано
- Связанные спецификации изменений: 0001, 0002, 0003
- Проверка: скрипты из раздела [«Как проверить»](#как-проверить)

## Назначение

`AGENTS.md` — документ, который coding-агент получает до пользовательского
запроса. Его задача — за один экран показать, что прочитать под конкретную
задачу, где источники истины, какие границы и в каком порядке работать.

Читатель — coding-агент. Документ не заменяет README и спецификацию, а
маршрутизирует к ним: ценность в ссылках и порядке действий, а не в
пересказе.

## На какие вопросы отвечает

| Вопрос | Ответ в `AGENTS.md` |
| --- | --- |
| Что главнее при конфликте документов? | Раздел «Приоритет документов» |
| Что читать под конкретную задачу? | Таблица «Что нужно → где смотреть» |
| Что обязательно, а что нужно только по ситуации? | Регламент и конституция обязательны; остальные документы — по потребности |
| Когда нужна спецификация изменения, а когда нет? | Раздел «Границы» и шаг 1 «Порядка работы» |
| В каком порядке работать? | «Порядок работы»: тип задачи → `spec.md` → `tasks.md` → реализация → проверка → `behavior/` → заморозка |
| Где искать детали, шаблоны и команды? | Ссылки на README уровней и шаблоны `changes/` и `experiments/` |
| Где лежит код и чем проверять? | `README.md` и `evaluation/README.md`; команд в `AGENTS.md` нет |

## Чего в AGENTS.md быть не должно

| Что | Почему | Где это должно быть |
| --- | --- | --- |
| Вводные фразы о самом файле | Файл целиком вставляется в контекст, описание себя — шум | — |
| Структура каталогов и описание проекта | Дублирует README | `README.md` |
| Команды сборки, запуска, проверки и флаги | Быстро меняются и дублируются | `README.md`, `evaluation/README.md` |
| Пересказ уровней спецификации, жизненного цикла изменений и полей эксперимента | Детали уже описаны в README уровней | `specification/*/README.md`, шаблоны |
| Текущее поведение, лимиты, версии, модели, цифры | Живые факты о решении | `specification/behavior/`, `data/` |
| История и обоснования решений | Это история, а не инструкция | `specification/changes/`, `specification/experiments/` |
| Планы и незавершённые идеи | Не являются текущим состоянием | `specification/changes/` |
| Новые правила процесса | Меняются через конституцию или спецификацию | `specification/constitution/`, `specification/changes/` |
| Обязательный список «прочитать всё» | Не привязан к задаче | Таблица по потребностям |
| Дублирование фактов из других документов | Источник расхождений | Один источник и ссылка на него |
| Секреты, ключи, локальные абсолютные пути | Не переносимы и небезопасны | Окружение |

## Ограничения

- Не больше 60 строк: документ должен читаться за один экран.
- Все пути указаны от корня репозитория и существуют.
- Одна ответственность — маршрутизация. `AGENTS.md` не источник истины.
- При изменении процесса документ обновляется в том же изменении.
- При расхождении с README или спецификацией прав тот документ, а
  `AGENTS.md` исправляется.

## Известные ограничения

- Автоматической проверки в CI нет: скрипты ниже запускаются вручную.
- Проверка «нет дублирования» частично ручная: `grep` ловит известные
  команды и заголовки, но не любой пересказ.

## Как проверить

```bash
# объём: не больше 60 строк
wc -l AGENTS.md

# все пути из таблицы документов существуют
sed -n '/^| Что нужно/,/^$/p' AGENTS.md |
  grep -oE '`[^`]+`' | tr -d '`' |
  while read -r p; do test -e "$p" || echo "MISSING: $p"; done

# нет известных признаков дублирования
grep -nE 'docker build|uv run|python -m evaluation|Где что лежит|до первого изменения' AGENTS.md
```

Ожидаемый результат: не больше 60 строк, нет `MISSING`, последняя команда
ничего не печатает.
