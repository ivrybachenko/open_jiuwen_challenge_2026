# Бюджет и выбор задач

- Состояние: частично
- Читатель: разработчик и coding-агент; организатор читает `README.md`
- Проверки: [таблица проверок](#как-проверить)

## Учёт токенов

Бюджет измеряется в выходных токенах. Стоимость вызова:

```
cost = output_tokens + ceil(input_tokens / 10)
```

- Токены рассуждений входят в выходные: API возвращает их в
  `completion_tokens`.
- Кеш провайдера не учитывается: все входные токены считаются полностью.
- `TokenTrackingRail` собирает расход по задаче, `TokenLedger` суммирует его
  по прогону.
- Бюджет задаётся флагами `--budget` или переменными `TOKEN_BUDGET`,
  `BUDGET`, `LLM_TOKEN_BUDGET`. Если бюджет не задан, лимита нет.

## Остановка по бюджету

- Перед каждой задачей проверяется условие `spent >= limit`.
- После задачи расход списывается; если он превысил лимит, задача уже
  записана в `solutions.json`, после чего прогон останавливается.
- Поэтому один прогон может превысить бюджет на стоимость последней задачи.

## Выбор задач

Сейчас выбор отсутствует:

- задачи берутся в порядке каталогов;
- баллы `reward` не влияют на порядок;
- нет оценки стоимости задачи до решения;
- нет отсева невыполнимых задач;
- нет переключения модели под задачу;
- нет параллельного решения нескольких задач.

Поля `solvable` и `impossible` из `task.json` использует только оценщик: он
не начисляет баллы за такие задачи. Харнесс эти поля не читает и всё равно
пытается решить задачу.

## Известные ограничения

Это главный разрыв с целями соревнования: харнесс не оценивает заранее
стоимость задачи, не выбирает самые выгодные задачи и не распознаёт
невыполнимые. Улучшения оформляются отдельными спецификациями в
[`../changes/`](../changes/README.md).

## Как проверить

Общие команды и флаги — в [`evaluation/README.md`](../../evaluation/README.md).
Все команды запускаются из корня репозитория, кроме harness-тестов, где нужен
`cd harness`.

| ID | Уровень | Что подтверждает | Проверка | Ожидаемо |
| --- | --- | --- | --- | --- |
| V-1 | быстрая | формула стоимости | `cd harness && uv run python -m unittest discover -s test` | все тесты OK |
| V-2 | интеграционная | остановка после превышения бюджета | `python -m evaluation.harness_task_set_checker --task-set data/task_set/example.yaml --budget <N>` | задача, превысившая бюджет, записана; следующая не запускается |

`<N>` — заведомо малый бюджет. Отчёт покажет баллы, расход токенов, стоимость
и время. Стоимость в отчёте сверяется с `solutions.json`; если поля `cost`
нет, применяется та же формула.
