## Назначение

`README.md` — точка входа для организатора и проверяющего. Он отвечает на
вопросы регламента соревнования и объясняет неочевидные решения, не требуя
читать спецификацию или код.

Читатель README — не разработчик. Ему нужно понять, как собрать и запустить
образ, куда попадут ответы, как считается расход, что происходит с
невыполнимыми задачами и какие следы остаются от прогона. Внутренние
контракты, параметры и критерии проверки ему не нужны.

`specification/behavior/` остаётся источником истины о текущем поведении и
проверках. README ссылается на него за деталями.

## Чего в README быть не должно

| Что | Почему | Где это должно быть |
| --- | --- | --- |
| Критерии приёмки и команды проверки поведения | Нужны разработчику, а не организатору | `specification/behavior/`, `specification/changes/` |
| История изменений, эксперименты и планы | Организатор читает текущее состояние, а не историю | `specification/changes/`, `specification/experiments/` |
| Процесс спецификации, `AGENTS.md`, жизненный цикл изменений | Внутренний процесс команды | `AGENTS.md`, `specification/README.md` |
| Текущие версии, баллы, модель по умолчанию, лимиты итераций и токенов | Меняются часто и устаревают | `harness/pyproject.toml`, `data/`, `specification/behavior/` |
| Параметры CLI и переменные окружения в полном составе | Дублируют `--help` и `behavior/` | `specification/behavior/01_runtime.md`, код |
| Устройство классов, rail'ов и внутренних вызовов | Не влияет на решение организатора | `specification/behavior/03_solver.md`, код |
| Незавершённые идеи как текущее поведение | Вводит в заблуждение | `specification/changes/` |
| Секреты, ключи, локальные абсолютные пути | Не переносимы и небезопасны | Окружение |

## Пересечение с behavior

Короткое пересечение с `behavior/` допускается и нужно: организатор не обязан
открывать инженерную спецификацию. Границы такие:

- README может повторять ответы на вопросы регламента: сборка и запуск,
  учёт расхода, невыполнимые задачи, траектории.
- README не копирует таблицы параметров, точные лимиты, версии, модели и
  критерии приёмки. Вместо этого он ссылается на профильный файл
  `behavior/`.
- Если факт меняется при каждом эксперименте или замере, его место в `data/`
  или коде, а в README — только ссылка.
- Если факт нужен организатору, чтобы собрать, запустить или понять решение,
  он остаётся в README, даже когда встречается в `behavior/`.

Проверка границы: «Поможет ли это организатору собрать, запустить или понять
решение?» Если нет — факт убирается или заменяется ссылкой.

## Стабильность

- Структура README и вопросы, на которые он отвечает, меняются редко.
- Команда сборки и запуска — публичный контракт; она сверяется с регламентом.
- Неочевидные детали фиксируются вместе с причиной, чтобы читатель понимал,
  почему решение выглядит именно так.
- Часто меняющиеся значения не переписываются в текст: версии — в
  `harness/pyproject.toml` и `uv.lock`, баллы и замеры — в `data/`, параметры —
  в `behavior/` и `--help`.

## Ограничения

- README не длиннее 160 строк: организатор должен найти ответ за несколько
  минут.
- Все относительные ссылки ведут на существующие файлы.
- README не обещает возможностей, которых нет в коде.
- При изменении сборки, запуска, учёта расхода, невыполнимых задач или
  траекторий README обновляется в том же изменении.
- При расхождении README и `behavior/` прав `behavior/`, а README исправляется.

## Известные ограничения

- Проверка «README не дублирует behavior» частично ручная: скрипты ловят
  известные признаки, но не любой пересказ.
- Автоматической проверки ссылок в CI нет: скрипт запускается вручную.
- README проверяет наличие ответов, но не качество их формулировок.

## Как проверить

```bash
# обязательные разделы
grep -nE '^## (Сборка и запуск|Учёт расхода|Невыполнимые задачи|Траектории|Неочевидные детали)' README.md

# команды регламента
grep -n 'docker build -t hack:latest' README.md
grep -n '/app/run_agent.py --tasks-dir /data/tasks' README.md
grep -n -- '--read-only' README.md

# ответы про файлы и текущие границы
grep -nE 'answer\.txt|solutions\.json|не распозна|не сохраня' README.md

# неочевидные детали
grep -nE 'read-only|filelock|мультимодаль|rg|git|digest|секрет' README.md

# в README нет критериев, истории и текущих значений
! grep -nE 'AC-[0-9]|Критерии приёмки|Supersedes|specification/changes' README.md
! grep -nE 'harness_version|--harness-version|qwen3\.|max_iterations|8192|version = "[0-9]' README.md

# все относительные ссылки существуют
grep -oE '\]\([^)]+\)' README.md | sed 's/^](//; s/)$//' |
  grep -vE '^(https?:|#|mailto:)' |
  while read -r link; do
    target=${link%%#*}
    test -z "$target" || test -e "$target" || echo "MISSING: $link"
  done

# объём
wc -l README.md
```

Ожидаемый результат: все разделы найдены, `MISSING` не печатается, README не
длиннее 160 строк, запрещённые формулировки и значения отсутствуют.
