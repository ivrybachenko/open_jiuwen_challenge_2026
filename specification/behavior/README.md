# Поведение решения

Живое описание того, как решение ведёт себя сейчас. В отличие от
[`../changes/`](../changes/README.md), эти документы не являются историей:
они обновляются вместе с кодом и всегда описывают текущее состояние.

## Зачем

Организаторы просят описать поведение решения: сборку и запуск, способ
оценки расхода, поиск невыполнимых задач и траектории. Этот раздел закрывает
эту задачу и служит точкой входа для проверяющего.

| Что просили описать | Где смотреть |
| --- | --- |
| Сборка и запуск | [01_runtime.md](01_runtime.md) |
| Способ оценки расхода | [04_budget_and_selection.md](04_budget_and_selection.md) |
| Поиск невыполнимых задач | [04_budget_and_selection.md](04_budget_and_selection.md) |
| Собранные траектории | [06_trajectories.md](06_trajectories.md) |

Отдельно зафиксирован контракт инструкций для coding-агента:
[08_agents_md.md](08_agents_md.md). Это внутренний процесс работы с
репозиторием, а не поведение решения для проверяющего.

## Правила

- Это источник истины о текущем поведении. Если документ и код расходятся,
  расхождение устраняется в том же изменении.
- Один файл — одна область контракта.
- Документ описывает наблюдаемое поведение и контракты, а не внутренние
  детали, если они не влияют на поведение.
- Изменение поведения оформляется спецификацией в `../changes/`. После
  реализации документ поведения обновляется, а спецификация изменения
  замораживается.
- Планы и незавершённые идеи не описываются как текущее поведение. Для них
  есть раздел «Известные ограничения» и спецификации изменений.
- Часто меняющиеся значения (лимиты, версии) указываются один раз и со
  ссылкой на источник; не дублируются в нескольких документах.

## Как обновлять

1. Изменение поведения начинается со спецификации в `../changes/`.
2. После реализации обновите затронутый файл поведения.
3. В спецификации изменения укажите, какой файл поведения она меняет.
4. Если изменение затрагивает устойчивое правило, обновите
   [`../constitution/`](../constitution/README.md).
