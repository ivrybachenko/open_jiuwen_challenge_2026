## Зачем

`README.md` — первый документ, который читает организатор, и единственный,
который регламент требует от команды. Сейчас он смешивает ответы на вопросы
регламента с внутренней политикой веток, подробностями запуска и истории,
поэтому нужный ответ приходится искать.

Одновременно `specification/behavior/` содержит точные контракты и критерии
проверки, которые организатору не нужны. Если требовать от README полного
отсутствия пересечений с `behavior/`, организатор останется без коротких
ответов на вопросы регламента. Поэтому граница проводится по читателю:
README даёт стабильную выжимку, `behavior/` — детали и проверки.

## Что меняется

1. `README.md` переписывается для организатора: короткая сводка, сборка и
   запуск, что происходит при запуске, учёт расхода, невыполнимые задачи,
   траектории, неочевидные детали, локальный запуск и карта документации.
2. Новый файл `specification/behavior/09_readme.md` фиксирует контракт README:
   читатель, обязательные вопросы, что в README не попадает, политика
   пересечения с `behavior/`, стабильность и проверка.
3. В таблицу состава `specification/behavior/README.md` добавляется строка о
   новом файле; назначение раздела `behavior/` уточняется: README — точка
   входа для организатора, `behavior/` — источник истины о поведении и
   проверках.
4. Внутренние сведения о версионировании переносятся из README в
   `data/harness_info/README.md`, чтобы README не обслуживал две аудитории.

## Ограничения

- Регламент соревнования — источник истины; README не обещает того, чего нет
  в коде.
- `behavior/` остаётся источником истины о текущем поведении; README ссылается
  на него, а не заменяет.
- README должен оставаться стабильным: меняющиеся цифры выносятся в данные и
  код, в тексте остаются инварианты и команды.
- Язык и стиль — как в остальной документации.

## Риски и откат

- **Риск:** README начнёт дублировать `behavior/` и расходиться с ним.
  Снижение: в README только сводка по вопросам регламента и ссылки; точные
  контракты и проверки остаются в `behavior/`.
- **Риск:** организатору не хватит деталей. Снижение: каждая тема содержит
  ссылку на профильный файл `behavior/` и `evaluation/README.md`.
- **Риск:** ограничение в 160 строк вытеснит неочевидную деталь. Снижение:
  убирать внутренние подробности, а не ответы на вопросы регламента.
- **Откат:** вернуть `README.md` из git, удалить `09_readme.md` и строку из
  состава; перенесённые сведения о версиях вернуть в README.
