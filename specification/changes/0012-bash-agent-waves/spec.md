## Зачем

`harness_v0001` передаёт агенту семь инструментов и системную инструкцию,
которая требует ReAct-цикл с инструментальными вызовами. Каждый ход содержит
описание инструментов, историю вызовов и ответы инструментов; на задачу
приходится медиана 4 хода. Стоимость почти линейно зависит от числа ходов, а
не от категории задачи.

Нужен харнесс, который:

- уменьшает постоянную часть промпта, убрав описание инструментов;
- уменьшает число ходов за счёт одного скрипта на ход и готового обзора
  рабочей директории;
- не тратит ход на ожидание, если `answer.txt` уже появился;
- умеет вернуться к перспективным задачам вторым ходом, когда первая волна
  прошла по всем задачам;
- собирает признаки сложности для будущего предсказателя;
- не падает из-за одной задачи, одного файла или одной ошибки модели.

## Что меняется

### Ответ агента — bash-скрипт

- deep-agent и набор файловых инструментов больше не используются.
- Агент получает короткий системный промпт на английском и первое сообщение
  в виде терминального обзора: `pwd`, `which python`, список файлов,
  заголовки датасетов, вывод найденных py-тестов и текст задачи.
- Любой ответ модели считается bash-скриптом. Если ответ содержит
  Markdown-блоки ```` ```bash ... ``` ```` (в том числе несколько), исполняется
  последний блок: провайдер иногда кладёт рассуждения в `content` вместе с
  несколькими черновиками. Если блоков нет, весь ответ исполняется as-is
  командой `cd <cwd> && bash <script>`.
- Вывод скрипта (stdout+stderr, код возврата, таймаут) возвращается агенту
  в следующем сообщении, если ход не завершён ответом.
- Ответом считается непустой `answer.txt` в рабочем каталоге или корне
  задачи. Если файл появился после хода, дополнительные вызовы модели в этом
  ходе не делаются.

### Обзор рабочей директории

Обзор строится до первого вызова модели и ограничен
`--overview-max-tokens` (по умолчанию 1500, оценка по символам).

- Список файлов обходится с ограничением числа просмотренных записей,
  глубины и числа показанных строк; лишние файлы сворачиваются в шаблоны
  вида `data/*.csv (N files)`.
- Каталоги `.git`, `__pycache__`, `.venv`, `node_modules` и подобные
  пропускаются. Символические ссылки не разыменовываются.
- Большие файлы не читаются целиком; в списке показывается размер.
- Для CSV/TSV/PSV показываются заголовок и пример первой строки. Если
  заголовки всех найденных датасетов совпадают, заголовок печатается один
  раз, а не для каждого файла. Слишком длинные заголовки и строки
  обрезаются.
- Если в рабочем каталоге есть `test*.py`, они запускаются до первого хода,
  а вывод (или отметка `PASS`) попадает в обзор. Запуск ограничен по времени
  и объёму вывода.
- Текст задачи всегда попадает в обзор; при нехватке лимита сначала
  сокращаются список файлов, датасеты и тесты, затем текст задачи.

### Волны

- **Волна 1.** Каждая задача получает ровно один ход модели с
  `--wave1-max-tokens` (по умолчанию 1000). Скрипт исполняется, ответ
  фиксируется, задача временно закрывается. Если ответа нет, задача остаётся
  кандидатом во вторую волну.
- **Волна 2.** Из незавершённых задач выбираются перспективные по эвристике
  ожидаемой пользы на токен. Каждая выбранная задача получает ровно один
  дополнительный ход с `--wave2-max-tokens` (по умолчанию 4000).
- Вторая волна продолжает историю первой: агент видит свой скрипт и вывод
  его исполнения.
- Если первая волна записала `IMPOSSIBLE`, задача не закрывается навсегда:
  предсказатель может счесть её перспективной, тогда `answer.txt` удаляется,
  а в сообщении появляется предупреждение перепроверить вывод. Если вторая
  волна не дала нового ответа, прежний ответ восстанавливается.
- Если первая волна не дала ответа из-за обрыва ответа модели, ошибки
  скрипта или таймаута, это отражается в предупреждении второй волны.
- Число задач второй волны ограничено `--wave2-max-tasks` (по умолчанию 50).
  Отбор идёт по `reward`, оценке вероятности успеха и потраченным токенам.

### Признаки сложности

Для каждой попытки сохраняются:

- рассуждение модели, его длина, время и ключевые слова;
- расход, `finish_reason`, признак обрыва по лимиту;
- скрипт: длина, наличие `python`, обращений к файлам, тестов, записи
  `answer.txt`;
- исполнение: код возврата, таймаут, объём вывода;
- ответ: отсутствует, `DONE`, значение или `IMPOSSIBLE`;
- категория, `reward`, номер волны.

Признаки пишутся в `bash_attempts.jsonl` в каталоге траекторий, если он
задан. Обучение регрессии в это изменение не входит: эвристика отбора
использует те же признаки, чтобы данные можно было накопить.

### Бюджет

- Агенту не сообщается ни бюджет, ни остаток, ни стоимость хода. В промптах
  нет слов `budget`, `tokens left`, `spending limit`.
- Харнесс проверяет бюджет перед каждым ходом и останавливается после
  превышения, записав текущую попытку.

### Устойчивость

- Ошибка обзора, модели, скрипта, чтения ответа, записи состояния или
  траектории не останавливает прогон.
- `solutions.json` перезаписывается после каждой попытки, а не только после
  задачи.
- Состояние попыток сохраняется в
  `<agent-workspace>/<task_id>/state.json`. При совпадении пути задачи
  прогон продолжается с сохранённого места, не повторяя уже сделанные ходы.
- После трёх подряд ошибок модели волна останавливается, чтобы не тратить
  время на недоступный прокси.

## Вне рамок

- Обучение регрессии сложности и загрузка модели в харнесс.
- Динамический выбор модели под задачу.
- Параллельное решение задач.
- Использование полей `solvable`/`impossible` из `task.json` как оракула.
- Повторные ходы сверх второй волны.

## Ограничения

- Регламент: один час на прогон, образ меньше 4 ГБ, бюджет токенов общий.
- Агент не должен знать о бюджете, иначе он может рассуждать о бюджете вместо
  задачи.
- `answer.txt` должен появиться в каталоге задачи; при наличии `workspace/`
  харнесс пишет оба файла.
- openJiuwen остаётся базой: вызовы модели идут через его
  OpenAI-совместимый клиент; deep-agent с инструментами не используется.
- Состояние и скрипты живут в `/tmp` и не переживают контейнер; переживает
  только повторный запуск процесса в том же контейнере.

## Риски и откат

- **Модель отвечает текстом вместо скрипта.** Скрипт упадёт, вывод вернётся
  агенту; вторая волна может исправить. Риск: лишний ход. Смягчение — снятие
  одного Markdown-забора и короткая инструкция.
- **Обрыв на 1000 токенах.** Рассуждения съедают лимит, скрипт не дописан.
  Риск: низкая доля ответов первой волны. Смягчение — признаки обрыва и
  вторая волна с большим лимитом.
- **Обзор слишком дорогой.** Ограничение по токенам и свёртка файлов.
- **Скрипт агента зависает или печатает гигабайты.** Таймаут, убийство
  группы процессов, обрезка вывода.
- **Потеря ответа при второй волне.** Прежний ответ сохраняется в состоянии
  и восстанавливается, если новый не появился.
- **Откат.** Вернуть тег `harness_v0001`; спецификация изменения остаётся
  историей.
