## Зачем

Сейчас `commit_harness_version` выдаёт один `run_id` на повтор прогона и
переиспользует его для всех задач и строки набора. В датасетах появляются
строки с одинаковым `run_id`, поэтому по этому полю нельзя однозначно указать
на результат одной задачи, удалить один замер или сопоставить строку с
отчётом. Поле выглядит как идентификатор строки, но им не является.

## Что меняется

- `new_run_id()` возвращает UUID версии 4, а не UTC-время с микросекундами.
  Два вызова даже подряд дают разные значения.
- `commit_harness_version` генерирует отдельный `run_id` для каждой записи:
  для каждой задачи в каждом повторе и для каждой строки набора. Общего
  `run_id` на повтор больше нет.
- Запись результата с `run_id`, который уже встречается в том же датасете у
  другой задачи (или другого набора), отклоняется с `ValueError`; файл не
  меняется. Повторная запись той же пары (`run_id`, задача/набор) по-прежнему
  обновляет строку.
- Исторические значения в `data/harness_task_score/harness_v_0001.tsv` и
  `data/harness_task_set_score/harness_v_0001.tsv` заменяются уникальными
  UUID. Значения выводятся детерминированно из старой строки, поэтому
  миграцию можно воспроизвести.

## Критерии приёмки

- [x] AC-1: два вызова `new_run_id()` возвращают разные строки, каждая — валидный UUID.
- [x] AC-2: один полный прогон `commit_harness_version` с двумя задачами и
  набором пишет в каждый датасет строки с попарно разными `run_id`.
- [x] AC-3: попытка записать второй результат с тем же `run_id`, но другой
  задачей или другим набором завершается `ValueError`, и датасет не меняется.
- [x] AC-4: в обоих текущих TSV-файлах `harness_v_0001.tsv` все `run_id`
  уникальны.

## Вне рамок

- Добавление отдельного столбца `batch_id` для связи повторов.
- Изменение формата, числа или порядка столбцов TSV.
- Пересчёт баллов, стоимости и времени в исторических строках.

## Ограничения

Миграция касается только датасетов версии `0001`. Новые датасеты заполняются
уже уникальными значениями. Ручной `--run-id` остаётся доступным, но при
конфликте с другой строкой запись отклоняется.

## Проверка

- `python -m unittest discover -s evaluation/test -t .` — тесты генератора,
  записи датасетов, полного замера и целостности текущих TSV.
- Проверка текущих файлов: для каждого `data/*/harness_v_*.tsv` число строк
  равно числу уникальных `run_id`.

## Риски и откат

Риск: потеря связи строк одного повтора после отказа от общего `run_id`.
Компенсация: такая связь и раньше не была формализована, а строки можно
группировать по времени записи; для явной группировки потребуется отдельное
изменение с полем `batch_id`. Откат — вернуть генератор на UTC-время и
восстановить прежние значения из истории git.
