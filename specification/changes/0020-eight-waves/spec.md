## Зачем

Версия `0004` разрешала четыре волны. На `example` это подняло средний балл с
16,2 до 17,4, но `search_0005` осталась нерешённой во всех пяти прогонах:
модель тратит ход на `grep` или `cat` и начинает писать ответ только на
пятом-шестом действии. Ограничение в четыре волны обрывает её раньше, чем она
сдаёт ответ. Замер с шестью ходами решал `search_0005` 3/3 за 659–901 токен,
поэтому предел волн поднимается до восьми.

## Что меняется

1. Значение по умолчанию для `--max-waves` / `HARNESS_MAX_WAVES` — 8.
2. Механика выбора не меняется: каждая волна пересчитывает вероятность
   успеха, отбирает кандидатов по `reward · P / стоимость`, проверяет остаток
   бюджета и ограничена `--wave2-max-tasks`.
3. На последней разрешённой волне (восьмой) предупреждение остаётся
   финальным; на промежуточных волнах оно не меняется.
4. Волны 3–8 по-прежнему используют модель и лимит второй волны; модель без
   ризонинга остаётся по умолчанию.

## Критерии приёмки

- [x] AC-1: без флага и переменной `max_waves=8`; флаг и переменная
      перекрывают значение.
- [x] AC-2: волны 5–8 выполняются для незавершённых задач и не повторяют уже
      выполненные волны.
- [x] AC-3: модель по умолчанию остаётся `qwen3.6-35b-a3b-noreason`.
- [x] AC-4: юнит-тесты проходят; 5 замеров набора `example` на версии `0005`
      записаны в `data/harness_task_set_score/harness_v_0005.tsv`.

## Ограничения

- Каждая дополнительная волна повторяет обзор и историю: ~150–400 токенов на
  поисковую задачу. На задачах, где модель зациклилась, восемь волн стоят
  дороже четырёх; отбор и остаток бюджета ограничивают расход.
- Больше волн не помогает задачам с неверным `answer.txt`: такой ответ
  считается сданным и не переотбирается.

## Проверка

- `cd harness && uv run python -m unittest discover -s test` — 74 теста OK.
- 5 × `python -m evaluation.harness_task_set_checker --task-set
  data/task_set/example.yaml --harness-version 0005 --record`.
- Сравнение с `harness_v_0004.tsv` по баллам и токенам.

Результат: 5 прогонов дали 20, 20, 20, 20, 18 (среднее 19,6) при стоимости
2878–3214 токенов (среднее 2998). Версия `0004`: среднее 17,4 при 2995;
версия `0003`: 16,2 при 2328. То есть восемь волн подняли средний балл на
2,2 при той же стоимости. Единственный провал — `coding_0003` в одном
прогоне: модель сдала `DONE` с неверным кодом, а такой ответ не
переотбирается. Контейнерный прогон на Linux (как у жюри) — 20/20 за
2800 токенов.

## Риски и откат

- Стоимость растёт на задачах, которые модель не может решить: каждая новая
  волна повторяет контекст. Проверка остатка бюджета останавливает прогон.
- Откат: `--max-waves 4` или `HARNESS_MAX_WAVES=4` без изменения кода.
