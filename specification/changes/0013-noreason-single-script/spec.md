## Зачем

Эксперимент `0003` сравнил reasoning-модель `qwen3.6-35b-a3b` (R) и
`qwen3.6-35b-a3b-noreason` (NR) на 32 задачах в четырёх прогонах. Главный
результат: требование «ровно один fenced-блок с полным скриптом» сильнее
выбора модели.

- `NR → NR` с таким форматом: 89,75 ± 4,27 балла из 97 при 15 574 токенах.
- `R → R` в обычном формате: 86,50 ± 6,35 балла при 36 661 токене.
- Гибрид `NR → R`: 83,25 ± 2,06 балла при 20 646 токенах.
- Разрешённый блок пояснений с извлечением «последнего блока» ломал
  исполнение: модель дробила ответ на несколько блоков, последним часто был
  `echo "DONE" > answer.txt`, и задача не решалась.

Нужно перенести проверенную конфигурацию в зачётный харнесс: NR по умолчанию,
один полный fenced-блок без пояснений. Это снижает стоимость и убирает
опасный режим, в котором пояснение меняет исполняемый скрипт.

## Что меняется

### Модель по умолчанию

- `DEFAULT_MODEL` становится `qwen3.6-35b-a3b-noreason`.
- Явные `--model` и `LLM_MODEL` по-прежнему перекрывают значение по умолчанию
  и принимают любую из четырёх разрешённых моделей.
- Харнесс не переключает модель между волнами: одна модель на прогон.

### Формат ответа

- Системный промпт требует **ровно один** fenced-блок с полным
  самодостаточным bash-скриптом.
- Промпт запрещает текст до и после блока; пояснения не нужны.
- Харнесс исполняет содержимое блока. Защитное поведение
  `extract_script` сохраняется: если модель всё же вернула несколько блоков,
  исполняется последний; если блоков нет, ответ исполняется as-is.
- Остальные требования промпта не меняются: один скрипт на ход, `answer.txt`,
  `DONE` для coding, `IMPOSSIBLE` для невыполнимых задач, проверка
  извлечённых значений.

### Версия

- Версия харнесса поднимается до `0003`; в `data/harness_info/harness_info.tsv`
  добавляется строка `0003` с описанием изменения.

## Ограничения

- Разрешены только четыре модели регламента; NR — одна из них.
- Агенту по-прежнему не сообщается бюджет.
- Контейнер read-only; формат ответа не должен требовать записи вне
  workspace.
- Один прогон ограничен часом; смена модели не должна добавлять вызовов.
- `answer.txt` остаётся единственным способом сдать ответ.

## Риски и откат

- **NR слабее R на сложных search-задачах.** В эксперименте `0003` R иногда
  решал `search/solvable/0002` и `0007`, а NR нет. Смягчение: `--model`
  позволяет вернуть R без изменения кода; при устойчивой деградации —
  откат.
- **Формат одного блока снижает исследовательскую свободу.** Модель обязана
  писать полный скрипт; если она всё же вернёт несколько блоков, сработает
  старое защитное поведение.
- **Ошибка в промпте ломает все задачи.** Смягчение: unit-тесты промпта и
  интеграционный прогон на `example.yaml`.
- **Откат.** Вернуть `DEFAULT_MODEL = "qwen3.6-35b-a3b"` и прежний
  `SYSTEM_PROMPT`, версию `0002`; спецификация остаётся историей.
