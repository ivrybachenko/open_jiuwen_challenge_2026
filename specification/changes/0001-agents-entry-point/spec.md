## Зачем

`AGENTS.md` — первый документ, который читает coding-агент. Сейчас он не
выполняет эту роль:

- в списке чтения нет `specification/changes/README.md`,
  `specification/experiments/README.md` и шаблонов, хотя агент обязан писать
  `spec.md`, `tasks.md` и записи экспериментов;
- перечислены не все типы изменений: «правило проекта» названо, но шагов для
  него нет, а рефакторинг и правка документации не упомянуты, поэтому агент
  может создавать лишние спецификации;
- шаг заморозки расходится с `specification/changes/README.md`: нет статуса
  `implemented`, удаления `tasks.md` и обратной ссылки `Superseded by`;
- не сказано, где лежит код и чем проверять изменение;
- текст пересказывает `specification/README.md` и уже отстал от него, что
  нарушает C-03 (один источник истины).

Цена ошибки — пропущенные обязательные артефакты, спецификация после кода
или лишняя бюрократия на рефакторинг.

## Что меняется

`AGENTS.md` становится коротким маршрутизатором и чек-листом, а не
самостоятельным источником правил. Новая структура:

1. **Назначение.** Одна-две строки: файл задаёт порядок чтения и работы;
   все пути — от корня репозитория; при конфликте документов приоритет:
   регламент → конституция → `behavior/` → остальное.
2. **Карта репозитория.** Где лежит код (`harness/src/harness/`,
   `harness/test/`), оценка (`evaluation/`), данные (`data/`), спецификация
   (`specification/`), регламент (`challenge_info/`).
3. **Что прочитать.** Таблица со ссылками и вопросом, на который отвечает
   документ:
   - `README.md` — сборка, запуск, проверка;
   - `challenge_info/problem_statement.md` — регламент (обязателен);
   - `specification/README.md` — уровни спецификации;
   - `specification/constitution/README.md` — правила проекта;
   - `specification/behavior/README.md` — текущее поведение;
   - `specification/changes/README.md` — жизненный цикл изменения;
   - `specification/experiments/README.md` — журнал гипотез;
   - `specification/changes/_template/spec.md` и `tasks.md` — шаблоны;
   - `specification/experiments/_template.md` — шаблон эксперимента.
4. **Границы.** Менять поведение — только через спецификацию изменения;
   рефакторинг и правка текста — без спецификации; замороженный `spec.md`
   не редактируется; регламент и конституция обязательны.
5. **Рабочий цикл.** Сначала тип изменения:
   - правило проекта → `specification/constitution/` + строка в таблице
     состава;
   - изменение поведения или контракта → `specification/changes/NNNN-slug/`;
   - гипотеза → `specification/experiments/NNNN-slug.md`;
   - рефакторинг или правка документации → спецификация не нужна.

   Затем общие шаги: `spec.md` до кода → `tasks.md` со ссылками на критерии
   приёмки → реализация → проверка с записью результата → обновление
   `behavior/` (для нового файла — строка в `behavior/README.md`) → заморозка
   (`implemented`, удаление или архив `tasks.md`, `Supersedes` и
   `Superseded by` в обе стороны). Для эксперимента запись делается до
   запуска и сохраняется даже при отрицательном результате.
6. **Ссылки на подробности.** У каждого шага — ссылка на README
   соответствующего уровня; команды и форматы в `AGENTS.md` не дублируются.

## Критерии приёмки

- [ ] AC-1: в `AGENTS.md` есть таблица чтения со ссылками на все документы
      из п. 3 раздела «Что меняется». Проверка: каждый путь из таблицы
      существует в репозитории.
- [ ] AC-2: в `AGENTS.md` есть блок «Рабочий цикл», явно покрывающий четыре
      типа изменений (правило, поведение, гипотеза, рефакторинг/документация)
      и шаги: спецификация до кода, задачи с критериями, реализация,
      проверка, обновление поведения, заморозка.
- [ ] AC-3: утверждения о жизненном цикле совпадают с
      `specification/changes/README.md` и
      `specification/experiments/README.md`: статус `implemented`, удаление
      или архив `tasks.md`, `Supersedes` и `Superseded by`, запись
      эксперимента до запуска, сохранение отрицательного результата.
      Проверка: сверка с указанными файлами по пунктам.
- [ ] AC-4: `AGENTS.md` начинается с краткого назначения (1–2 строки),
      укладывается в 80 строк и не содержит команд сборки, запуска или
      проверки — только ссылку на `README.md`.
      Проверка: `wc -l AGENTS.md`; поиск `docker build`, `uv run`,
      `python -m evaluation`.
- [ ] AC-5: все пути в `AGENTS.md` указаны от корня репозитория и
      существуют; в таблице чтения нет ссылок только на директории без
      входного файла. Проверка: скрипт из раздела «Проверка».
- [ ] AC-6: изменение не трогает код и данные.
      Проверка: `git diff --name-only` содержит только `AGENTS.md` и файлы
      в `specification/changes/0001-agents-entry-point/`.

## Вне рамок

- Переписывание `specification/README.md` и других документов.
- Новые правила процесса: `AGENTS.md` только точно пересказывает
  существующие и ссылается на них.
- Изменения runtime-кода, `README.md`, регламента и данных.

## Ограничения

- Язык и стиль — как в остальной документации (русский, короткие абзацы и
  таблицы).
- Объём — не больше 80 строк, чтобы файл читался целиком.
- Никаких новых команд, цифр и лимитов: они берутся из `README.md` по
  ссылке.
- C-02: у файла одна ответственность — маршрутизация агента.
- C-03: один источник истины; детали остаются в README уровней.
