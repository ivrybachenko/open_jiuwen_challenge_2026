# AGENTS.md

Точка входа для coding-агентов. Здесь только то, чего нет в остальной
документации: порядок чтения, границы ответственности агента и минимальный
рабочий цикл.

## Проект

Харнесс кодового агента для OpenJiuwen Challenge 2026. Решает задачи в
пределах общего бюджета токенов и сохраняет ответы. Регламент соревнования —
в `challenge_info/problem_statement.md`.

## Что прочитать до первого изменения

| Документ | На какой вопрос отвечает |
| --- | --- |
| `README.md` | Как собрать, запустить и проверить решение |
| `specification/README.md` | Как устроена спецификация и куда что писать |
| `specification/constitution/` | Какие правила действуют для всего проекта |
| `specification/behavior/` | Как решение ведёт себя сейчас |
| `challenge_info/problem_statement.md` | Что требуют организаторы |

Конституция и регламент обязательны. Файл поведения нужен для той области,
которую затрагивает изменение.

## Рабочий цикл

1. Определи тип изменения: правило проекта, поведение или гипотеза.
2. Для изменения поведения напиши `spec.md` в
   `specification/changes/NNNN-slug/` до кода. Для гипотезы — запись в
   `specification/experiments/`.
3. Составь `tasks.md` со ссылками на критерии приёмки.
4. Реализуй изменение и проверь его по этим критериям.
5. Обнови затронутый файл `specification/behavior/`.
6. Заморозь `spec.md`; следующее изменение оформляй новым со ссылкой
   `Supersedes`.

Подробности — в `specification/README.md`.
