# repo_size_checker

Измеряет размер репозитория и сравнивает его с лимитом регламента: меньше
100 МБ без учёта `.git`. По умолчанию считаются файлы, отслеживаемые git, —
именно они попадают в клон, который проверяет жюри. Локальные `.venv`, `out` и
другие неотслеживаемые каталоги в зачёт не идут, но показываются отдельно,
чтобы было видно, что занимает место.

```bash
# полная проверка: метрика по умолчанию — отслеживаемые файлы
python -m evaluation.repo_size_checker

# что занимает место: разбивка по каталогам верхнего уровня и крупные файлы
python -m evaluation.repo_size_checker --top 0 --largest 10

# весь рабочий каталог без .git (включая локальные .venv и out)
python -m evaluation.repo_size_checker --metric without-git

# всё вместе с историей git
python -m evaluation.repo_size_checker --metric total

# свой лимит и свой файл отчёта
python -m evaluation.repo_size_checker --max-mb 50 --out out/reports/size.json
```

Метрики:

- `tracked` (по умолчанию) — суммарный размер файлов из `git ls-files`;
- `without-git` — размер рабочего дерева без `.git`;
- `total` — всё, включая `.git`.

Символические ссылки не разворачиваются, поэтому обход не зацикливается.
Чтение идёт одним проходом по дереву; файлы, к которым нет доступа,
пропускаются, как в `du`. Считается логический размер файлов, а не занятые
блоки диска, поэтому результат может быть меньше, чем показывает `du -sh`
(на APFS — заметно меньше).

JSON-отчёт пишется в `out/reports/repo_size_check.json` (переопределяется
`--out`) и содержит все три размера, разбивку по каталогам верхнего уровня,
крупнейшие файлы и вердикт. Коды возврата: `0` — размер в пределах лимита,
`1` — превышен, `2` — не удалось запустить проверку.
