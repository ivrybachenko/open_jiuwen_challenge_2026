# Журнал экспериментов

Одна запись — одна проверенная гипотеза. Отрицательный результат — тоже
результат: он избавляет следующего разработчика от повторной проверки.

## Когда запись нужна

- проверяем эффект модели, параметра, стратегии или набора задач;
- сравниваем несколько вариантов решения;
- повторяем прошлый эксперимент в новых условиях;
- проверяем гипотезу перед тем, как писать спецификацию изменения.

## Когда запись не нужна

- изменение уже принято, и нужно описать поведение — это
  [`../../specification/changes/`](../../specification/changes/README.md);
- рутинный прогон без гипотезы (smoke-тест, проверка сборки) — достаточно
  отчёта инструмента.

## Структура

```
experiments/
  _template.md
  NNNN-slug.md
  NNNN-slug/          # только если у эксперимента есть свои артефакты
    experiment.md
```

По умолчанию хватает одного файла. Директория создаётся, только если рядом с
записью нужно хранить конфигурации или другие небольшие артефакты. 

- `NNNN` — сквозной номер из четырёх цифр.
- `slug` — короткое имя эксперимента латиницей через дефис.

## Обязательные поля

1. **Гипотеза** — что проверяем и какой результат подтвердит гипотезу.
2. **Условия** — версия харнесса или коммит, модель, набор задач, бюджет,
   команда запуска и всё, что нужно для повторения.
3. **Результат** — измеренные величины и ссылки на данные и отчёты.
4. **Вывод** — гипотеза подтверждена, опровергнута или результат
   неубедителен; почему.
5. **Решение** — что делаем дальше: спецификация изменения, откат, повтор с
   другими условиями или ничего.

## Правила

- Условия должны позволять повторить запуск без устных пояснений автора.
- Данные и отчёты не дублируются в записи; на них даётся ссылка.
- Отрицательные и отменённые эксперименты не удаляются.
- Если эксперимент привёл к изменению поведения, в записи есть ссылка на
  спецификацию изменения.
- Если спецификация изменения основана на эксперименте, в ней есть ссылка на
  запись эксперимента.
